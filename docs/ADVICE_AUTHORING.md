# دليل تأليف بطاقات الإرشاد — «إرشاد» (D59)

هذا الدليل هو العقد بين الكاتب (بشري) والحارس الآلي
(` scripts/validate-advice.mjs `). أي بطاقة لا تمرّ المدقّق لا تصل إلى
المزارع. الأرقام هنا محسوبة من البيانات الفعلية لا من الذاكرة.

## القواعد المطلقة

1. **لا تشخيص.** كل بطاقة تبدأ بـ«تأكد أولاً»: علامات تُراها + ما قد
   يُشبهها + فحص يطلبه المختص. التطبيق يطلب التأكيد ولا يُقرِّر.
2. **لا جرعات.** أي رقم موصوف بوحدة تطبيق (مل · لتر · كغ · هكتار ·
   دونم · فدان · ٪ · ppm) داخل أي نص عربي = فشل المدقّق. الجرعة
   والتسجيل من الملصق المحلي حصراً.
3. **لا منتجات تجارية.** أسماء الشركات داخل الخيارات الكيميائية =
   فشل. المواد بالمادة الفعّالة واسمها الدولي فقط.
4. **لا اختراع.** كل ادعاء مربوط بمصدر ` source_ids ` موجود فعلياً في
   قائمة مصادر البطاقة، وكل مصدر مُستخدم من بند واحد على الأقل.
5. **روابط متحقّقة.** الرابط ` https ` بتاريخ فحص ` retrieved ` بصيغة
   YYYY-MM-DD. أي رابط ميت يُكتشف بأمر ` --check-links ` (فحص حيّ لكل
   الروابط؛ نطاق FAO يرفض الفحص الآلي فيُعامل تحذيراً موثّقاً لا
   فشلاً).

## سياسة الترخيص — البديل عند غياب الأذونات

لم تُتحصل أذونات إعادة النشر من EPPO ولا PPDB؛ البطاقات تكتب **سياق
الاستشهاد والتلخيص العلمي** (` cite_and_paraphrase `): لا لصق نصوص
الأصل، بل تلخيص عامة مع اسم الجهة والرابط. التصنيف في
` advice-registry-report.json `: كل المصادر ` cite_only ` إلى أن
تصل الأذونات الواردة (تُدار باسم صاحب المشروع). المصدر المفتوح
الموثّق يُدرَج في ` license_policy.open_licensed `.

## ملف الحزمة

```
data/advice/
  manifest.json                 # المحاصيل + أسماءها بالإنجليزية والفرنسية
  modifiers.json                # ستة مفاتيح ملف المزرعة مع en/fr
  <crop>.json                   # بطاقة أو أكثر لكل محصول
  advice-registry-report.json   # يُعاد توليده مع كل تحقّق ناجح
```

` manifest.owner_initial_cards ` يحمي البطاقات الثلاث الخاصة بالمالك من
الحذف أو التعديل الصامت (تُقبل الإضافة لا الإطاحة).

## بنية البطاقة

| الحقل | الشرط |
|---|---|
| ` id ` | فريد عالمياً، قالب a-z0-9- |
| ` problem ` | ` name_ar ` + ` type ` من القائمة + ` aliases_ar ` |
| ` status ` | draft أو reviewed (reviewed يتطلب مراجعين وتاريخاً) |
| ` local_status ` | libya: verified أو unverified + ملاحظة |
| ` confirm_first ` | intro ≥ 40 حرفاً + signs ≥ 2 + lookalikes ≥ 1 |
| ` cultural ` · ` non_chemical ` · ` prevention ` | إلزامي ≥ بند واحد |
| ` nutrition ` | اختياري (يُسمح بالفراغ مع بقاء المصفوفة) |
| ` chemical ` | ` note_ar ` إلزامي؛ الخيارات فارغة تتطلب اعتذاراً صريحاً |
| ` see_expert_when_ar ` | ≥ 2 |
| ` sources ` | ≥ 1 وكلها مستخدمة |

- **الدليل** ` evidence ∈ {A,B,C}`: A أساس قوي · B أساس جيد · C دليل
  أولي. يظهر شارة في الواجهة.
- **الشرط** ` applies_if `: كائن مفاتيحه من ` modifiers.json ` وقيمته
  مصفوفة من قيمه. بند بشروط غير مضبوطة يُخفى ويُعدّ في تلميح «أكمل
  الملف» — لا يُعرض أبداً على مزارع لا ينطبق عليه.
- **الكيمياء**: ` moa_scheme ∈ {FRAC,IRAC,HRAC} ` + ` moa ` بصيغة
  رقمية أو M رقم + مكوّنات ` ar ` و ` en ` + توقيت وتحذير بلا جرعة.

## إضافة محصول جديد

1. أنشئ ` data/advice/<crop>.json ` بنفس البنية (انسخ أقرب نظير).
2. أضف مدخله في ` manifest.json ` (اسم عربي وإنجليزي وفرنسي).
3. أضف الملف إلى ` SHELL ` في ` sw.js **وفي** ` DECLARED_ADDED.SHELL `
   في ` tests/ppocr-size.test.mjs ` (الحارس يرفض أي إضافة غير معلَنة).
4. شغّل ` npm run test:advice ` — المدقّق يتحقق والتقرير يُعاد.
5. إن احتاج نص جديد مفتاحاً، أضفه ×4 في ` src/i18n.js `.

## مسار الإصابات (D61) — نبات ← نوع ← إصابة

بطاقات الإصابات المرقّمة لا تُكتب يدوياً ولا تُخترع: تُولَّد من ثلاثة أدلة فقط.

1. **الحصاد** — `node scripts/advice-harvest.mjs [offset] [limit]`: لكل مرشّح
   صفحة EPPO (العنوان يحسم) وقائمة آفاته (Major host ثم Host) ومطابقة GBIF
   مقبولة. المخرج `data/advice/evidence/<id>.json`. المرشّح بلا دليل يُرفض
   ويُسجّل سببه.
2. **التصنيف** — `node scripts/advice-pest-taxonomy.mjs`: يجمع الآفات الفريدة
   ويصنّفها من GBIF؛ من بلا تطابق يُصنَّف من اسمه المعلن فقط إن حمل
   «virus/viroid/phytoplasma» حرفياً، وإلا يبقى unknown فلا بطاقة ولا قائمة.
3. **الديوان** — لكل آفة رئيسية ملف `_dossiers/<CODE>.json`: اسم عربي +
   مصدر https واحد مُتحقَّق منه + مظاهر ≥2 + علاج ≥1 + evidence. لا ديوان بلا
   مصدر، ولا بطاقة خارج ديوان.
4. **التوليد** — `node scripts/advice-generate.mjs`: يكتب
   `data/advice/dossiers.json` + `data/advice/infections/<id>.json` (النواة:
   الأنواع والبطاقات المرقّمة — تُجهَّز مع القشرة) +
   `data/advice/infections/<id>.ref.json` (القائمة المرجعية — عند الطلب) +
   يحدّث manifest بالمحاصيل والميتا.
5. **الحارس** — `npm run test:advice`: المدقّق يطابق كل بطاقة بقائمة EPPO
   وبتصنيف GBIF ويتسلسل ترقيمها؛ أي مظاهر بلا ديوان أو جرعة داخل ديوان = فشل.

إضافة محصول جديد لإصاباته: أضف مرشّحه في `scripts/advice-harvest.mjs` ثم
شغّل الحصاد والمصنّف والتوليد؛ النواة الجديدة تحتاج إعلاناً في
`DECLARED_ADDED.SHELL` (المرجعية لا تُعلن لأنها خارج الحزمة).

## الأوامر

```
npm run test:advice                    # بنية + جرعات + نظافة + تقرير
node scripts/validate-advice.mjs --check-links   # فحص حيّ للروابط
```
