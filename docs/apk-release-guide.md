# دليل ملفي APK للإصدارين التجريبيين (خطوة بخطوة)

> هذا دليل للمالك. لا ملف APK بُني ولا رُفع شيء إلى أي متجر؛ بناء الملف يتم من موقع
> `pwabuilder.com` بحساب المالك، لأن بيئة العمل هنا لا تحوي أدوات أندرويد.

## 1) هل نستطيع التحديث بعد رفع APK؟

نعم. التطبيق من نوع Trusted Web Activity، أي أن الملف غلاف يفتح الموقع نفسه.

| نوع التغيير | هل يحتاج ملف APK جديد؟ |
|---|---|
| بطاقات، بيانات، نصوص، تصميم، إصلاحات (كل ما ننشره على الموقع) | لا، يصل لكل المستخدمين تلقائياً عند فتح التطبيق |
| تغيير الأيقونة أو الاسم أو ألوان الإطلاق في ملف manifest | نعم، يُعاد البناء |
| تغيير إعدادات الغلاف الأصلية (الاتجاه، ملء الشاشة) | نعم |
| رفع رقم الإصدار في المتجر | نعم، ملف جديد برقم أعلى |

شرط جوهري: **المفتاح الذي يوقَّع به الملف يجب أن يبقى نفسه في كل تحديث**. إن ضاع المفتاح لا يمكن تحديث التطبيق في المتاجر، ويضطر المستخدمون لحذفه وتثبيت تطبيق جديد.
احتفظ بملف المفتاح وكلمات سره في ثلاثة أماكن (حاسوبك، ذاكرة USB، بريدك الخاص)، ولا يُرفع إلى GitHub.

## 2) الرابطان

لكل إصدار رابط نشر خاص به، فيُبنى لكل منهما ملف APK مستقل:

| | الإصدار الأول (حفظ ومرجع) | الإصدار الثاني (الحالي) |
|---|---|---|
| الفرع | `release-1-pre-oct11-preserved` | `experimental-v2-tawsiyat-text-2026-10-29` |
| الرابط | مشروع Pages جديد (الخطوة 3) | `https://al-mustashar.pages.dev` |
| معرّف الحزمة المقترح | `ly.almustashar.app.v1` | `ly.almustashar.app` |
| اسم التطبيق المقترح | المستشار الزراعي (تجريبي 1) | المستشار الزراعي |

اختلاف معرّف الحزمة ضروري ليُثبَّت الإصداران معاً على الجهاز نفسه وليكون لكل منهما صفحة في المتجر.

## 3) إنشاء رابط الإصدار الأول (مرة واحدة، مجاني)

1. Cloudflare ثم Workers and Pages ثم Create ثم Pages ثم Connect to Git.
2. اختر المستودع `al-mustashar` واسم المشروع `al-mustashar-v1`.
3. Production branch: `release-1-pre-oct11-preserved`. اترك Build command و Output directory فارغين.
4. بعد النشر يصبح الرابط `https://al-mustashar-v1.pages.dev`.
5. عطّل Automatic production branch deployments في هذا المشروع إن أردت تثبيته نهائياً.

أرسل لي صورة بعد كل خطوة وسأؤكد قبل الانتقال للتي تليها.

## 4) بناء ملف APK لكل إصدار (PWABuilder)

1. افتح `pwabuilder.com` والصق رابط الإصدار، ثم Start.
2. انتظر التحليل، ثم Package for stores ثم Android ثم Generate.
3. أدخل: Package ID كما في الجدول، App name، Version 1.0.0، وفعّل Signing key: Create new.
4. نزّل الملف المضغوط. فيه: ملف APK، وملف AAB، وملف المفتاح، وملف نصي بكلمات السر وبصمة SHA-256.
5. احفظ المفتاح وكلماته فوراً كما في الفقرة 1.

## 5) ربط الموقع بالتطبيق (assetlinks.json)

دون هذه الخطوة يعمل التطبيق لكن يظهر شريط عنوان المتصفح أعلاه.
أعطني بصمة SHA-256 لكل إصدار (من الملف النصي في الخطوة 4، وهي ليست سراً) وأنا أضيف الملف `/.well-known/assetlinks.json` للموقع وأنشره، فيختفي الشريط.
في الإصدار الأول يلزم إضافة الملف إلى فرعه المحفوظ، وهذا تعديل واحد صغير سأنفّذه فقط بعد موافقتك الصريحة لأنه يمس الفرع المرجعي.

## 6) الرفع إلى متجر مجاني

| المتجر | ملاحظة (تُتحقق قبل التسجيل لأن الشروط تتغير) |
|---|---|
| Uptodown | رفع مجاني عبر بوابة المطورين، يراجع الملف يدوياً |
| Aptoide | متجر مفتوح، يمكن إنشاء متجر خاص بك مجاناً |
| APKPure | يقبل رفع المطورين مجاناً |
| Samsung Galaxy Store | التسجيل مجاني لكن يطلب بيانات تحقق |
| Huawei AppGallery | مجاني لكن يطلب توثيق هوية |

التسلسل المقترح: رفع الإصدار الثاني أولاً إلى متجرين، ثم الإصدار الأول بمعرّفه المختلف.
نص صفحة المتجر: وصف قصير، لقطات شاشة (4 على الأقل من وضعي المزارع والمحترف)، وأيقونة 512. أجهزها لك عند الوصول لهذه الخطوة.

## 7) بعد كل رفع

- أعد تشغيل `node scripts/post-deploy-smoke.mjs <رابط الإصدار>` للتأكد من سلامة الموقع.
- جرّب الملف على هاتف حقيقي: يفتح بلا شريط، ويعمل دون اتصال بعد أول تشغيل.
