## 4) خوارزمية البصمات — كاملة بلا التباس

هذا الجدول يستخدم **خوارزميتين مختلفتين**، وخلطهما_مستبعَدة خطأ:

| | البصمة القصيرة (7 محارف) | البصمة الطويلة (64 محرفاً) |
|---|---|---|
| **الخوارزمية** | **Git blob object ID** = SHA-1 على ترويسة `blob <length>\0` + المحتوى | **SHA-256 على بايتات المحتوى الخام** |
| **الأداة** | `git ls-tree` (وكثيراً `git hash-object`) | `sha256sum` على الملف · `crypto.createHash('sha256')` في `tests/data-health.test.mjs` |
| **ماذا تقيس** | **هوية كائن Git** (تتحرك لو تغيّر أي بايت، وتعرف هل الملفان نفس الكائن) | **قيمة الملف** (لا صلة لها بـGit) |
| **أمثلة** | `24e853d` · `7cb048a` · `38db530` · `630e19d` | `b6850e03…` · `9a1427e0…` · `b24d7c3e…` · `ef629525…` |

**تحقّق من الخلط:** استخرجتُ محتوى الـblob عبر `git cat-file -p` ثم
`git hash-object --stdin` ⇒ أعاد **`24e853d4c4ed3962460edab2e3bcfbc2bf258b9f`**
بالضبط، فمعرّف الـblob هو **Git blob SHA-1 لا غير**. وكذلك SHA-256 للـblob
المستخرج = SHA-256 للملف المحفوظ بالضبط ⇒ لا فرق فراغات لاحقة.

**الخلاصة:** `24e853d` **و** `b6850e03…` لملف واحد — **رقمان مختلفان لنفس
المحتوى**، لأن الأول Git والثاني قيمة. الجدول يُميّزهما بالعمودين.
