# تصميم التعرف البصري — المرحلة د (جولة v2)

> الحالة: **تصميم وواجهات فقط في هذه الجولة** — لا محرك ثانٍ منشور، ولا طبقة سحابية
> منشورة، ولا تدريب. الخط الأساسي ينتظر الصور (قرار المستخدم: «لاحقًا»).

## د1 — الخط الأساسي الحقيقي (بانتظار الصور)

- الموقع: `tests/fixtures/labels/` + `ground-truth.csv` (الأعمدة:
  `image_file, printed_active_ingredient, printed_cas, condition, notes` —
  يكتبها المستخدم من قراءته للملصق).
- التنفيذ: كل صورة عبر المسار الحقيقي: التقط → معالجة → Tesseract الحالي
  → استخراج → **طبقة الحكم judge.js** → النتيجة.
- الأعمدة لكل صورة: المادة المقروءة، النتيجة المعروضة، الزمن، عدد المحاولات،
  صحيح؟، نوع الخطأ (**قبول خاطئ** / رفض خاطئ / لا قراءة).
- المقياس الحاكم: **القبول الخاطئ = 0** شرط النشر التجريبي. عيّنة n تعطي
  حدًا أعلى 95% ≈ 3/n: سبع عشرة صورة ≈ 18% فقط — النتيجة الإيجابية
  المحدودة لا تثبت السلامة، والقبول الخاطئ الواحد يوقف التوسع.
- التقرير يُكتب في `docs/ocr-baseline.md` (يُستبدل القالب عند وصول الصور).

## د2 — الواجهة الموحدة للمحرك (مطبقة في src/ocr.js — تُراجع ولا تُكرر)

```
scan(file, opts) -> Promise<{
  lines?:  [{ text, conf, bbox }],   // عند توفر TSV
  words?:  [{ text, conf, bbox }],
  text: string,                       // النص الخام للنص الفائز
  cas:   [string], candidates: [string],
  passes: n, variant, psm, aiRegion?
}>
```

المحرك الحالي (Tesseract.js 6.0.1, eng+ara, multi-pass V2) هو التنفيذ
الوحيد خلف هذه الواجهة الآن. أي قارئ مستقبلي يُلفّ بنفس العقد دون تغيير
سلوك الاستدعاء.

## د3 — مسابقة المرشحين (تصميم؛ التنفيذ بعد الخط الأساسي)

| # | المرشح | خطة التقييم |
|---|---|---|
| 1 | Tesseract.js (الحالي) | القارئ المرجعي |
| 2 | PP-OCRv6 small/medium، نماذج مستضافة ذاتيًا عبر onnxruntime-web | يُقاس: الحجم (≈30/134MB)، الذاكرة، الزمن، الدقة على نفس المجموعة وبالمقياس نفسه. لا يصبح افتراضيًا إلا بقرار المستخدم بعد رؤية أرقام مقارنة. لا يغطي العربية رسميًا — يبقى قارئًا ثانيًا لاتينيًا |
| 3 | قراءة سحابية | **مسابقة الاختبار فقط** إن توفرت مفاتيح بيئة + موافقة. لا يُنشر أبدًا بهذه الجولة |

أرقام المطورين المنشورة لا تُعتمد — القياس على صور المستخدم هو الحَكَم.

## د4 — مسار القراءة المعتمد (طبقات)

1. **التقاط بأعلى دقة:** `getImageData` محدود الأبعاد (سقف قائم)، لقطات
   متعددة أثناء تدوير العبوة مع اختيار الأوضح (يُقاس لاحقًا بالحدة).
   بديل الالتقاط في فايرفوكس أندرويد: `capture` عادي + اختيار من المعرض.
2. **قراءة على مقاطع بدقتها الأصلية** لمنطقة المكونات (AI-region موجود
   في V2 — يبقى، ويُقاس أثره على الخط الأساسي).
3. **قارئان محليان مستقلان:** 1 + 2 عند ثبوت 2 — الحكم المؤكد يستلزم
   تطابق قارئين، أو رقم CAS بنجاح رقم التحقق.
4. **تحقق حتمي:** طبقة الحكم `judge.js` (تام/احتمالي/ملتبس) — لا ثقة
   ذاتية من أي قارئ.
5. **تأكيد بشري دائم:** خطوة عرض النص المستخرج وتعديله قبل البحث
   (منفذة — تُراجع في الواجهة).
6. **فشل آمن:** «لم أستطع القراءة بثقة، أدخل الاسم يدويًا» — لا تخمين.

**قاعدة الحكم المؤكد:** CAS بنجاح رقم التحقق ومطابق لسجل، أو اسم تام قرأه
قارئان مستقلان. غير ذلك: «احتمالي».

## د5 — الطبقة السحابية الاختيارية (عقد التصميم فقط — لا نشر)

```
REQUEST  : { image: bytes, consent: true }         // بعد موافقة صريحة + إفصاح
RESPONSE : {
  lines:       [ { text, region } ],
  ingredients: [ { printed_text, normalized_name, basis } ],
  //            basis: latin_text | arabic_text | inferred_from_brand
  cas_numbers: [ { printed_text } ],
  unreadable:  true | false
}
```

- التعليمات للمزوّد: «انقل النص كما هو ولا تصحّح؛ ما لا تقرأه أعد
  `unreadable`» — **لا نسبة ثقة ذاتية أبدًا**.
- الاسم المستنتج `inferred_from_brand` لا يُحكم به — يعرض «احتمالي».
- **قراءة رجوع:** كل ناتج سحابي يُقصّ من الصورة الأصلية ويُعاد قراءته
  بالمحرك المحلي؛ الاختلاف = رفض الناتج السحابي.
- اختبار الاستنتاج: هل كل اسم في `ingredients` موجود حرفيًا داخل
  `lines`؟ الغائب = استنتاج — يُحسب ويُسجل.
- الخصوصية: موافقة صريحة قبل أي رفع + إفصاح «الصورة تغادر الجهاز».
  لا عبارة «لا يتم تخزينها» إلا بعد التحقق من صحتها لدى المزود.

## د6 — التشخيص المحلي (منفذ — يبقى)

سجل كل مسح (محاولات، متغير فائز، زمن، نتيجة) في التخزين المحلي دون
الصورة، مع تصدير ملف يدوي. لا إرسال تلقائي.

## د7 — مولّد البيانات التركيبية (سكربت مستقبلي — تصميم)

يولّد ملصقات بأسماء مواد حقيقية من `data/*.json` بخطوط/خلفيات/انحناء/
ضبابية متعددة، خارج المنصة، لضبط نموذج قراءة لاحقًا بحساب تدريب مجاني.
لا يُشغَّل في هذه الجولة.

## د8 — حماية الموارد (منفذة — تُراجع)

ميزانية زمن حسب الجهاز، مؤشر تقدم، زر إلغاء، سقف أبعاد، إعادة تدوير
العامل. مسح كامل 180 ثانية غير مقبول — يُقاس في الخط الأساسي ويُخفَّض
إن لزم.
